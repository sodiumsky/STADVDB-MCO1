# Rules for code written in this repo

- Write comments only to explain why, never what the code does.
- Use no emojis or decorative symbols in code, logs or comments. Use plain ASCII.
- Reuse existing functions and helpers before creating new ones.
- Never add a wrapper that does nothing.
- Follow the naming and formatting conventions of the surrounding files.
- Use only libraries and language features already present in the project.
- Keep solutions as small as the task allows.
- Verify that any API you call exists in the installed version.
- Write tests that can actually fail and cover edge cases.
- Handle errors where failures are realistic (network, files, the database) and nowhere else.
- Make small, focused commits with messages that follow the repo convention: a short imperative sentence, such as "Remove the unused queries_previos.js".
- Do not edit the ETL scripts in scripts/ unless asked. They belong to their author.
- Before finishing any task, be ready to explain every line you wrote.
